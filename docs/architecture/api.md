# API

All endpoints live under `/api/v1/`. Writes and owner-scoped reads require `Authorization: Bearer <token>`. The token is `FAIR_DEV_TOKEN` when `AUTH_PROVIDER=dev`, or a Hanko-issued JWT when `AUTH_PROVIDER=hanko`. `GET` on datasets, local-models, and predictions is open anonymously for rows with `visibility="public"`. Anonymous callers get 404 on private rows.

The running backend's OpenAPI schema covers every endpoint, including base models, categories, feedback, stars and user state. [Release QA](release-qa.md) uses these endpoints in run order.

| Path | Format |
| --- | --- |
| `/api/docs/` | Swagger UI, with a request body for each write endpoint |
| `/api/redoc/` | ReDoc |
| `/api/schema/` | Raw OpenAPI |

## Core flow endpoints

| Method | Path                                               | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------ | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/health/`                                         | Dependency reachability report                                                                                                                                                                                                                                                                                                                                                                                                    |
| POST   | `/aois/`                                           | Create an AOI polygon (GeoJSON Feature)                                                                                                                                                                                                                                                                                                                                                                                           |
| GET    | `/aois/`                                           | List AOIs (bbox-filterable)                                                                                                                                                                                                                                                                                                                                                                                                       |
| POST   | `/datasets/build/`                                 | Enqueue a dataset build job. `title`, `description`, `category`, `aoi_ids`, `imagery` (TMS template per model input name, such as `{"image": ...}` or `{"post": ..., "pre": ...}`) or `source_imagery` (one template, read as `image`), `zoom`, `label_tasks`, `keywords` (training needs one the base model's `keywords` also has), `label_type`, `geometry_type`, `imagery_quality` (WebP quality of `imagery_pmtiles`: `high` by default, `medium` or `lossless`). ## Validation endpoints

Users answer yes or no for each tile of a built dataset or a prediction with `results_ready`, signed in or as a guest. Guests' reads are throttled per IP by `VALIDATION_READ_NETWORK_RATE_LIMIT`, in place of `ANON_RATE_LIMIT`; signed-in reads fall under `USER_RATE_LIMIT`. Validation project responses include `respondent_count`, the number of distinct signed-in users and `guest_id` values that answered.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/validation/projects/` | Published and finished projects, plus the caller's drafts (all drafts for admins). Filter by `type`, `status`, and `source_id`, one dataset STAC id or prediction id (projects whose `source_ids` include it) |
| GET | `/validation/projects/{id}/` | One project. Drafts are visible only to the owner and admins. A GET on a draft that has been `building` for longer than `VALIDATION_BUILD_TIMEOUT` seconds queues its build again |
| POST | `/validation/projects/` | Create a draft. Body: `source_ids`, `type` (`training` or `prediction`), `title`, `description`, `answers_needed` (1 to 9, default 1). For a training project, `source_ids` lists 1 to 5 distinct built dataset STAC ids on the same single imagery input and zoom; their tiles and labels are merged into one project. A training project may set `class_map`: each key is a `property=value` class from a source's STAC `label:classes`, and each value is the class shown on tiles, for example `{"roof:material=metal_sheet": "metal"}`. Classes left out keep their own value. Returns 400 for a key that none of the sources declare, and for a non-empty `class_map` on a prediction project. For a prediction project, `source_ids` holds one prediction's numeric `id` with `results_ready`, one imagery input and at least one feature. The caller owns every source, or is an admin. Returns 202 and builds `tiles.bin`, `imagery.pmtiles` and `labels.pmtiles` in the background; `build_status` moves from `building` to `built`, or to `failed` with the reason in `build_error` |
| PATCH | `/validation/projects/{id}/` | Owner or admin. Edit `title`, `description` or `answers_needed` (400 for a change to `source_ids`, `type` or `class_map`), or move `status` from `draft` to `published` (400 until `build_status` is `built` and every source is public) or from `published` to `finished`; 400 once finished |
| POST | `/validation/projects/{id}/build/` | Owner or admin. Build the files again. Returns 202 with `build_status` set to `building`; 400 unless the project is a draft |
| POST | `/validation/projects/{id}/answers/` | `answers`, a list of 1 to 50 `{"tile_id", "valid"}` objects (`tile_id` is the PMTiles tile id), and `guest_id` (a UUID) when signed out; 400 without it. Returns 204; a respondent's new answer for a tile replaces their earlier one. 404 on a draft, 410 once finished. Answers for tiles outside `tiles.bin` are stored but left out of `done.bin` and `results.parquet`. Throttled per account by `VALIDATION_ANSWER_RATE_LIMIT` and for guests per IP by `VALIDATION_ANSWER_NETWORK_RATE_LIMIT`; `USER_RATE_LIMIT` and `ANON_RATE_LIMIT` do not apply |
| GET | `/validation/projects/{id}/files/{name}/` | Redirect to a presigned URL for `tiles.bin`, `imagery.pmtiles`, `labels.pmtiles`, `done.bin` or `results.parquet`. 404 for any other name; for `done.bin` and `results.parquet` until the first refresh writes them; and for anyone but the owner and admins while any source is private. The other three files exist once `build_status` is `built` |

| File | Content |
| --- | --- |
| `tiles.bin` | The project's PMTiles tile ids in ascending order, each an 8-byte little-endian unsigned integer |
| `imagery.pmtiles` | WebP tiles at one zoom. Metadata holds `zoom` and the tile count `tiles` |
| `labels.pmtiles` | Labels or predicted features as vector tiles at the imagery zoom, layer `labels` |
| `done.bin` | Bit `i` (least significant bit first) is the `i`-th id in `tiles.bin`, set once that tile has at least `answers_needed` answers |
| `results.parquet` | One row per answered tile: `tile_id`, `z`, `x`, `y`, `yes`, `no`, `valid` (the majority; null below `answers_needed` answers or on a tie) and `geometry`, the tile polygon in EPSG:4326 |

A worker writes `done.bin` and `results.parquet` when a project is published, every `VALIDATION_REFRESH_INTERVAL` seconds while it stays published, and once more when it is finished.
